# MCP και RAG της έκδοσης NetLogik

Ο πλήρης κατάλογος προσφέρεται από τρία εργαλεία MCP. Η αναζήτηση δεν εκτελεί τις υπηρεσίες των παρόχων.

| Εργαλείο | Χρήση |
|---|---|
| `api_catalog_search` | Αναζήτηση ονομάτων, περιγραφών και κατηγοριών, με φίλτρα παρόχου/κατηγορίας |
| `api_catalog_get` | Πλήρης εγγραφή από το σταθερό ID, με flags και παραπομπές στην αρχική πηγή |
| `api_catalog_stats` | Μεγέθη, κατηγορίες, πάροχοι, source commit και SHA-256 του καταλόγου |

Παράδειγμα ροής:

```json
{"tool":"api_catalog_search","args":{"query":"Booking hotel","category":"travel","limit":5}}
```

Έπειτα καλούμε `api_catalog_get` με ένα πραγματικό ID από τα αποτελέσματα. Η αναζήτηση απαιτεί να εμφανίζονται όλοι οι όροι· για ελεύθερη ελληνική περιγραφή ο βοηθός επιλέγει σύντομους αγγλικούς όρους. Τα ελληνικά ονόματα κατηγοριών υποστηρίζονται απευθείας. Οι περιγραφές και οι τιμές του snapshot παραμένουν ισχυρισμοί των αρχικών πηγών, με σχετική επισήμανση.

## Εγκατάσταση σε συμβατό NetLogik MCP host

1. Εκτέλεσε `python3 netlogik/build_catalog.py` και επαλήθευσε το `netlogik/dist/artifact-manifest.json`.
2. Εγκατάστησε ατομικά το `netlogik/dist/catalog.runtime.json` στη σταθερή διαδρομή `/opt/netlogik-kb/catalogs/api-mega-list/catalog.json` του host. Ο loader δέχεται κανονικό αρχείο έως 64 MiB και απορρίπτει symlinks.
3. Εγκατάστησε το ελεγμένο [api-catalog.mjs](../netlogik/mcp/api-catalog.mjs) στο σύστημα `tools.d` του NetLogik MCP. Το module απαιτεί το υπάρχον contract `register(server, {z, text, err})` και δεν είναι αυτόνομος MCP server.
4. Άνοιξε νέα σύνδεση MCP ή χρησιμοποίησε τον dispatcher `addon_invoke` για τα νεότερα εργαλεία. Έλεγξε ότι το `api_catalog_stats` επιστρέφει 11.981 εγγραφές και το σωστό hash.

Το module φορτώνει τον κατάλογο στην πρώτη κλήση, διαβάζει αποκλειστικά τη σταθερή διαδρομή, ελέγχει το schema και περιορίζει το μέγεθος των απαντήσεων. Δεν εκκινεί shell, δεν διαβάζει credentials και δεν κάνει δικτυακές κλήσεις. Η προέλευση μιας πολύ μεγάλης εγγραφής μπορεί να εμφανίζεται περικομμένη στο MCP· όλα τα αρχικά δεδομένα παραμένουν στο gzip και στην τοπική CLI.

```bash
node --test netlogik/mcp/api-catalog.test.mjs
```

## Σημασιολογική ανακάλυψη στο RAG

Η ενσωμάτωση NetLogik χρησιμοποιεί **35 οδηγούς**: έναν κεντρικό οδηγό `api-mega-list-library`, 23 βασικές κατηγορίες, 3 παρόχους και τις 8 συνταγές του [RECIPES.md](RECIPES.md). Οι κάρτες ανακάλυψης βρίσκονται στο ανεξάρτητο namespace `api-mega-list:` και παραπέμπουν στα πλήρη κείμενα `skill_read` ή `memory_read`. Διαθέτουν embeddings με τα υπάρχοντα μοντέλα `nomic-embed-text` και `paraphrase-multilingual`.

```json
{"tool":"kb_semantic_search","args":{"query":"τιμές ξενοδοχείων και κρατήσεις","source_prefix":"api-mega-list:","limit":5}}
```

Οι 11.981 εγγραφές αναζητούνται ολόκληρες από τα εργαλεία καταλόγου. Το RAG ευρετηριάζει τους οδηγούς επιλογής και αξιοποίησης· δεν αποθηκεύει ως embeddings κάθε γραμμή του καταλόγου. Αυτή η διάκριση διατηρεί ακριβή την ανάκτηση IDs, URLs και αρχικής προέλευσης.

Τα εσωτερικά records MCP/RAG έχουν ταξινόμηση `internal`. Η οργάνωση, η αναζήτηση και οι προσαρμογές NetLogik δεν παρέχουν δικαιώματα ιδιοκτησίας ή δωρεάν πρόσβαση στις υπηρεσίες των παρόχων.
